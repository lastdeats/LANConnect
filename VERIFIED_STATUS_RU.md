# LAN Connect • TAMBOV — проверенный статус

19 ноября 2026, Москва. Разработка продолжается. **Готовых EXE/APK нет.**
Продолжена сохранённая версия исходного проекта; Android-клиент создан заново.

## Последнее продолжение: подготовка настоящих сборок

Подключение GitHub подтверждено. Доступных репозиториев пока нет; проект
никуда не загружался, GitHub Actions не запускался. Подготовлен workflow
`.github/workflows/build.yml`: проверки, отдельные Windows и Android jobs,
фиксированные SHA официальных Actions, отчёты и выбранные артефакты.
Подробности и конкретный следующий шаг — BUILD_RU.md.

Windows-сборщик теперь проверяет готовые EXE перед выдачей результата.
Клиент имеет служебный режим проверки Tk/Pillow/ABI; сервер — изолированный
HTTP/HTTPS-тест с временной базой. Добавлен план сборки отдельного TLS-инструмента.
На текущем Linux выполнена серверная проба из **Python-исходников**, не EXE.

Android-сборщик разделяет dev-подпись и постоянный ключ, передаёт пароли через
окружение, проверяет manifest/DEX/структуру и подпись, сохраняет JSON-отчёт.
Искусственные APK-контракты проверены тестом без SDK. Это не реальный APK.
Нативные сборщики пока не запускались до получения двоичных файлов.

## Ранее: разные Android-устройства

Цель — Android 8.0+ на популярных марках, без зависимости от Google-сервисов.
Подробный отчёт и план аппаратной проверки: android/COMPATIBILITY_RU.md.
Добавлены запасные режимы микрофона/динамика 16/48/44,1 кГц, потоковый
пересчёт PCM с фильтром, системный audio focus, обработка заглушения/отказа
микрофона, запасной выбор файла и подсчёт неизвестного размера потоком.
Понижено потребление памяти: 100 сообщений/100 файлов в Android-состоянии,
ограничение декодируемых кадров. Добавлены адаптация кнопок по ширине и
сведения об устройстве ⓘ. Добавлен локальный контроль согласия: поздний ответ сети после Стоп не
возобновляет сеанс; старый опрос не стирает новое разрешение. Системный
диалог микрофона обрабатывается с учётом паузы/возврата Activity.
Ничего из этого не проверялось на телефоне.

Общий код пяти компонентов Android скомпилирован в байткод Java 8
и исполнен на JDK 21: пересчёт звука, fallback-политика, ограниченные потоки,
расчёт размеров кадров и отмена запоздалого согласия. Это настоящий запуск общего Java-кода, но не Android
API, не тест микрофона/динамика и не APK. Синтаксис всех 8 Java-исходников
проверен отдельно. Сборка APK и совместимость по маркам не подтверждены.

## Ранее добавлены история и проверка целостности

- Добавлена единая постраничная история сообщений и файлов: общий порядок по времени, ID и виду записи; страницы не пересекаются. В Windows и Android добавлено отдельное окно истории с переходами «Раньше», «Новее», «Последние».
- Добавлен защищённый запрос метаданных файла по ID. Windows может скачать старый файл, даже если его уже нет в последних 300 записях основного состояния.
- Сервер сохраняет SHA-256 каждого нового файла и отдаёт его с метаданными. В Windows добавлена потоковая проверка частичного/полного скачивания перед заменой итогового файла; в Android проверка выполняется при скачивании.
- Повреждённый временный файл Windows не выдаётся как успешно скачанный. Для старых записей без SHA-256 остаётся только проверка размера — прошлым файлам контрольные суммы задним числом не присваивались.
- Автополучение Windows разделено по серверу/пользователю, чтобы одинаковые ID и имена с разных серверов не использовали один путь.
- Добавлены тесты истории и целостности; расширена проверка сохранения SHA-256 через HTTP.

## Ранее добавлено на предыдущем этапе

- Добавлен серверный live-протокол: аудио, JPEG-экран и отдельное право управления. Без согласия владельца передача запрещена. Есть завершение, сроки действия, лимиты очередей/кадров, защита от повторных аудиопакетов, ограничение одновременных сеансов.
- В Windows-клиент добавлены запрос/приём звонка, захват/воспроизведение звука через WinMM, показ и захват основного экрана через Pillow, ограниченные щелчки/клавиши/Unicode-ввод. Есть заметное окно активного доступа и локальная остановка до сетевого уведомления.
- Добавлены исходники нативного Android-клиента Java: регистрация, вход, люди/группы, чаты, создание/приглашения, выбор/передача файлов частями с хешем и продолжением отправки, скачивание потоком, аудиозвонки, просмотр и ограниченное управление Windows-экраном.
- Android запрашивает системное разрешение микрофона. При сворачивании активный сеанс закрывается. Камера и видеозвонки не добавлены.
- Добавлен HTTPS, генератор локальных сертификатов, инструкции доверия и проверка имени/цепочки. Windows-транспорт поддерживает LAN_CA_CERT и запрещает перенаправления/неявные прокси; Android тоже не пересылает токен при перенаправлении и подключается напрямую.
- Ограничены серверные сетевые обработчики (128) и live-сеансы (16). Очереди находятся в памяти, не записываются в файлы.
- Добавлены скрипт сборки Android из установленного SDK без Gradle, обновлён сборочный скрипт Windows и документация.
- Сохранены предыдущие исправления квоты, резерва диска, отмены загрузки, прав групп и хранения файлов 10 дней.

## Что действительно проверено

Среда: Linux, Python 3.12. Все сетевые проверки выполнялись через loopback
127.0.0.1, а не на устройствах пользователя.
`python run_tests.py --tls --android-core` — 13 сценариев, включая общие
Java-тесты, искусственные APK-контракты, исходную серверную пробу HTTP/HTTPS
и прежнюю статическую проверку автополучения. Проверка 5 ГиБ запускается отдельно.

| Проверка | Результат и границы |
|---|---|

## Что блокирует подтверждение готовности

В доступной среде нет Windows/Wine и PyInstaller; запуск Windows GUI
и WinMM/SendInput невозможен. Tk тоже не имеет графического дисплея.
Android SDK отсутствует. Проверочный запуск build_android.py завершился
на проверке зависимостей с сообщением «Android SDK не найден».
Java-компилятор доступен через модуль JDK, но одного его недостаточно для APK.
Никаких EXE/APK или инсталляторов не выдавалось и не подменялось архивом.
GitHub уже подключён; следующий сборочный блокер — отсутствующий доступный
репозиторий, а не неподключённый аккаунт.

Для завершения нужны сборка с Android SDK, сборка Windows, проверка реальных
Windows/Android устройств, маршрутизируемых подсетей, звука, задержки,
масштабирования и остановки ввода. Нужны также испытания нагрузки,
обработки аварийного отключения питания и обновления без потери данных.

Известные функциональные ограничения: Android-звонки только на открытом
экране приложения, нет push/фоновых вызовов; Android не передаёт свой экран;
нет перетаскивания/сочетаний клавиш/UAC-управления; мобильное скачивание
повторяется с начала; основной UI Windows показывает до 500 сообщений/300 файлов,
Android запрашивает до 100 сообщений/100 файлов; для более старых записей добавлено отдельное постраничное окно истории (GUI на устройствах не проверен).
TLS не включён без настройки; HTTP остаётся тестовым режимом.

## Воспроизведение

```
python run_tests.py --tls --android-core
```

Python и его стандартная библиотека. Отдельные документы: README_RU.txt,
README_REMOTE.txt, TLS_RU.md, android/README_RU.md.
