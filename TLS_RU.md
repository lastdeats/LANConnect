# HTTPS в автономной сети

Сервер поддерживает HTTPS с локальным сертификатом. Никаких внешних запросов
для выдачи сертификата или работы приложения не требуется.
HTTP оставлен для локальных тестов; перед реальной передачей паролей,
микрофона или удалённого управления настройте HTTPS.

Если будет успешно собран LANConnect-TLS.exe, он заменяет команду Python:
`LANConnect-TLS.exe --out tls --ip <IP-сервера>`. Сам EXE пока не собран.

1. На подготовительном компьютере установить Python-пакет `cryptography`
   (в этой среде проверено с 50.0.0).
2. Создать сертификат с **настоящим IP сервера**:

   ```
   python setup_tls.py --out tls --ip <IP-сервера>
   ```

   `--ip` можно повторить для нескольких адресов. Для имени — `--dns <имя>`.
   Выходная папка должна быть пустой: ключи не перезаписываются.
3. На сервере задать LAN_TLS_CERT полным путём к `tls/server-cert.pem`
   и LAN_TLS_KEY полным путём к `tls/server-key.pem`, затем запустить сервер.
   По умолчанию используется тот же TCP-порт 8080. Например, в Windows cmd:

   ```
   set "LAN_TLS_CERT=C:\LANConnect\tls\server-cert.pem"
   set "LAN_TLS_KEY=C:\LANConnect\tls\server-key.pem"
   LANConnect-Server.exe
   ```

4. Передать клиентам **только lan-ca.crt**, сверив его SHA-256 отпечаток
   с отпечатком, напечатанным setup_tls.py. Ключи `*-key.pem` не передавать.
   Закрытый ключ CA следует убрать с сервера в защищённое место после выдачи.
   Для работы сервера нужны сертификат сервера и его закрытый ключ.
5. Windows: импортировать `lan-ca.crt` в доверенные корневые центры
   сертификации текущего пользователя через мастер сертификатов.
   В Windows также можно вместо импорта перед запуском клиента задать
   LAN_CA_CERT полным путём к `lan-ca.crt`. Приложение читает доверие
   при запуске; после изменения доверия клиент нужно перезапустить.
   Android: установить его через системные настройки как сертификат CA.
   Android-клиент настроен доверять системным и установленным пользователем CA.
   Импорт корневого CA — отдельное осознанное действие владельца устройства.
6. В клиентах указать `https://<тот-же-IP>:8080`. Адрес должен быть
   перечислен в сертификате. Проверку сертификата отключать не нужно.

Сертификат сервера действует 365 дней, CA — 10 лет. Для обновления нужны
новый сертификат и предусмотренная процедура замены; автоматического
обновления в этой версии нет. Закрытые ключи не защищены паролем, поэтому
доступ к ним должен быть ограничен средствами Windows.

Проверено здесь: запуск HTTPS, регистрация, отказ при недоверенном CA и
несоответствующем имени. Импорт доверия и работа упакованных клиентов на
Windows/Android пока не проверены. HTTP и HTTPS не включаются одновременно
на одном порту: с заданными переменными сервер принимает только HTTPS.
