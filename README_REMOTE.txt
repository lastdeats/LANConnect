LAN Connect — сеансы аудио, экрана и управления

Новый транспорт /live/ хранит данные только в оперативной памяти.
У каждого сеанса криптографически случайный ID, но сам ID не даёт доступ:
проверяются токен участника, его роль и согласие владельца.
Ранее существовавший /remote/ — только старый протокол согласования;
новые клиенты не используют его для передачи данных.

Запрос активен 60 секунд. Владелец решает, принимать ли его.
Просмотр экрана и управление запрашиваются раздельно.
В режиме view команды ввода запрещены сервером.
После завершения либо истечения сеанса кадры, команды и аудио удаляются
из оперативной памяти и новые запросы к сеансу отклоняются.
Без обновлений сеанс истекает через 30 секунд, общий предел — 1 час.
Истечение проверяется при обращениях к live-протоколу.
После перезапуска сервера сеансы не восстанавливаются автоматически.

Windows-клиент показывает отдельное окно активного доступа со Стоп.
Закрытие окна/клиента останавливает локальный захват и ввод прежде,
чем отправляется сетевое уведомление о завершении.
При потере связи клиент прекращает локальный сеанс.
Передаётся только основной экран (JPEG до 1280x720, примерно 4 кадра/с).
Управление: левый/правый щелчок, ограниченный набор отдельных клавиш,
ввод Unicode-текста до 256 символов. Перетаскивания, сочетаний клавиш,
буфера обмена и управления повышенными/UAC-окнами здесь нет.

Аудио: mono PCM16 little endian, 16000 Гц, до 100 мс (3200 байт) на пакет.
Ограниченные очереди сбрасывают старые пакеты, чтобы не копить звук.
Нужны проверки качества, задержки, устройств и одновременных звонков.
Рекомендуются наушники при тестировании (эхоподавление не подтверждено).

Android-клиент может инициировать/принять аудиозвонок, просматривать
и ограниченно управлять Windows-экраном. Для аудио запрашивается
RECORD_AUDIO, запись начинается только после согласия сторон.
При сворачивании приложения активный сеанс закрывается.
Передачи экрана Android и управления Android через Accessibility нет.

Пока это исходники, а не проверенный удалённый рабочий стол.
HTTPS настраивается через TLS_RU.md; работа по HTTP не шифруется.
Сервер может читать передаваемые аудио/экран; сквозного шифрования нет.
